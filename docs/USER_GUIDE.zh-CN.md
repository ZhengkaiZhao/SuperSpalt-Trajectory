# SuperSpalt Trajectory 中文操作手册

本文说明本地启动、模型编辑、人工轨迹打点、真实相机读取、图片位姿匹配、实时 Pose 和 COLMAP/OpenCV W2C 外参导出。

## 1. 环境与启动

### 1.1 必要环境

- Node.js 22.0 或更高版本；项目推荐目标为 Node.js 24.19.0 LTS。
- 支持 WebGPU 的新版 Google Chrome 或 Microsoft Edge。
- NVIDIA RTX 并非必需，但大规模高斯模型建议使用独立显卡。

可用以下命令确认版本：

```sh
node --version
npm --version
```

### 1.2 Windows

- 普通启动：双击 `start-windows.cmd`。
- RTX 专用启动：双击 `SuperSplat RTX.cmd`。
- 完整修复：在命令行运行 `start-windows.cmd --repair`。

启动脚本会先显示已安装、最低支持和推荐 Node.js 版本。缺失或低于最低版本时必须安装；低于推荐版本但仍受支持时可以暂不升级。Windows 默认询问是否通过 `winget` 安装 Node.js LTS。普通启动器会优先使用 Chrome，并携带高性能 GPU 参数；RTX 启动器还会使用独立的 Chrome 用户配置，避免普通 Chrome 进程忽略 GPU 参数。

### 1.3 macOS

首次运行：

```sh
chmod +x start-macos.command
./start-macos.command
```

脚本会检查 Node.js 版本；需要升级时可通过 Homebrew 安装 `node@24`。随后优先以 Chrome 应用窗口启动；若 Chrome 不存在，会回退到系统默认浏览器。

### 1.4 启动器行为

启动器会执行以下检查：

1. 显示项目、操作系统、Node.js、npm、直接依赖数、锁定包数、构建和校验状态。
2. 验证 Node.js 不低于 22.0，并提示推荐的 24.19.0 LTS。
3. 仅在 `node_modules` 缺失、`package-lock.json` 更新或指定 `--install` 时运行 `npm ci --no-fund`。
4. 安装严格服从锁文件，不使用 `npm update`，普通启动不会改变声明或锁定版本。
5. 源码、配置、Node.js 版本或平台变化后默认执行依赖一致性、ESLint、语言包、核心逻辑测试和 TypeScript 检查；成功结果会缓存，未变化时直接复用。
6. `dist/index.js` 缺失、源码更新或指定 `--rebuild` 时执行构建。
7. 从端口 `3011` 开始寻找可用端口，最多尝试 20 个端口；服务仅监听 `127.0.0.1`。

RTX 启动器在首次缺少依赖或构建时，会在启动窗口中完成安装、检查和构建，再启动后台服务。后续双击时，如果 3011 服务和 release 构建均未变化，会直接恢复并置顶已有 RTX 窗口；如果构建已更新才会重启专用 Chrome。需要排查浏览器或 GPU 状态时，可运行 `SuperSplat RTX.cmd -Restart` 强制重启专用窗口，这不会关闭普通 Chrome。

启动与恢复参数：

| 参数 | 作用 |
| --- | --- |
| `--install` | 强制按锁文件重新安装依赖 |
| `--check` | 强制执行全部质量检查 |
| `--rebuild` | 强制重新生成 `dist/` |
| `--repair` | 依次强制安装、检查和构建 |
| `--setup-only` | 完成环境准备后退出，不启动服务器 |
| `--no-check` | 本次启动跳过检查，不建议用于发布 |
| `--port=3020` | 指定首选端口 |
| `--strict-port` | 端口被占用时直接报错 |
| `--no-open` | 不自动打开浏览器 |

## 2. 界面与基础操作

### 2.1 加载模型

支持将以下格式直接拖入编辑器：

- `.ply`
- `.splat`
- `.sog`
- `.ksplat`
- `.spz`
- `.ssproj`

也可从“场景/Scene”菜单打开文件。加载后，模型会出现在场景管理器中。

### 2.2 相机控制

| 操作 | 功能 |
| --- | --- |
| 鼠标左键拖动 | 环绕观察 |
| 鼠标中键拖动 | 推近或拉远 |
| 鼠标右键拖动 | 平移视角 |
| 双击模型 | 设置环绕中心 |
| `F` | 聚焦选择内容 |
| 方向键 | 平移或前后移动相机 |

### 2.3 模型变换

在场景管理器中选择模型后，可使用移动、旋转和缩放工具。需要特别注意：相机外参和最终使用的 PLY 必须位于同一个世界坐标系。

如果导出 Pose 前修改了模型变换，则必须满足以下一种情况：

1. 将变换烘焙进最终使用的 PLY；或
2. 使用本工具导出的、已经反变换回参考 PLY 世界坐标系的 Pose。

不要使用编辑器变换后的相机 Pose 去渲染未变换且未作为参考解析的另一份 PLY。

## 3. 人工打点轨迹

### 3.1 打开面板

点击右侧工具栏的相机轨迹按钮，打开“人工打点轨迹”悬浮面板。

### 3.2 创建轨迹

1. 使用“新建轨迹”创建 A、B、C 等独立轨迹。
2. 将相机移动到第一个目标视角。
3. 点击“记录当前视角”。
4. 移动到下一个视角并继续记录。
5. 使用“上一个点”“下一个点”检查已有关键点。
6. 使用“覆盖当前点”修正当前关键点，或使用“删除当前点”移除错误点。

同一位置和朝向不会被无意义地重复记录。至少需要两个有效关键点才能生成插值轨迹。

### 3.3 生成与校验

1. 在“最终相机数量”中输入目标帧数，例如 `81`。
2. 点击“结束打点并检验”。
3. 红色轨迹表示插值目标，蓝色轨迹表示 COLMAP 导出后回读得到的验证轨迹。
4. 显示“COLMAP 回读检验通过”后再执行正式导出。

“最终相机数量”不能小于人工关键点数量。需要继续修改时，点击“继续打点”。

### 3.4 预览

点击“预览插值轨迹”可按最终轨迹播放。按 `Esc` 或点击“停止”退出预览。

## 4. 真实相机参考

### 4.1 推荐目录结构

```text
dataset/
├─ images/
│  ├─ image_0001.jpg
│  └─ image_0002.jpg
└─ sparse/
   └─ 0/
      ├─ images.txt
      └─ cameras.txt
```

其中：

- `images.txt` 必需，保存已注册图像的 COLMAP 外参。
- `cameras.txt` 可选，用于读取相机模型和 FOV。
- 原始图片可选；提供原图后可进行像素匹配、预览和原文件快速命中。

### 4.2 加载步骤

1. 在“真实相机参考（绿色）”区域点击“选择 COLMAP 文件夹”。
2. 选择数据集根目录，而不是只选择 `sparse/0`。
3. 等待状态栏显示位姿数量和匹配到的原图数量。
4. 从下拉框选择真实图片进行预览。
5. 点击“设为首点”，将该真实相机 Pose 设为当前轨迹的第一个关键点。

当文件夹中存在多个 `images.txt` 时，工具依次比较：原图匹配数量、有效注册相机数量、目录深度和路径名称，优先选择最可能的真实数据集，而不是误选虚拟轨迹目录。

## 5. 拖入图片匹配相机 Pose

### 5.1 使用方法

将 PNG、JPEG 或 WebP 拖入“拖入任意参考图”区域，或点击“选择图片”。

匹配候选包括：

- 已加载 COLMAP 数据集中的真实相机；
- 人工记录轨迹的关键点或插值点；
- 当前规划器预览轨迹；
- 时间轴中未归属虚拟轨迹的真实参考相机。

### 5.2 匹配结果含义

结果会显示：

- 最大概率候选名称；
- 真实或虚拟来源；
- 相对概率；
- 图像相似度；
- 高、中、低置信度；
- 已评估候选数和总候选数。

除字节完全一致的真实原文件外，普通图片不会被宣称为百分百匹配。即使最大概率候选明显领先，也应结合画面、相机位置和备选结果人工确认。

旋转匹配使用 15 度粗搜加 5 度局部细化，兼顾速度和方向精度。匹配只旋转用于比较的图像描述符，不会把图片旋转或镜像补偿写入相机 Pose。

## 6. 实时相机 Pose

右上角性能 HUD 第一行显示 FPS、GPU 类型、轨迹状态和 `POSE` 开关。

1. 点击 `POSE`，展开当前相机参数。
2. `C` 表示参考 PLY 世界坐标中的相机中心。
3. `Qwxyz` 表示标准 COLMAP/OpenCV W2C 四元数，顺序为 `w,x,y,z`。
4. 点击复制图标可复制 `C_world`、`forward_world`、`q_w2c_wxyz` 和 `t_w2c`。

实时面板使用矩阵变化缓存；静止视角不会重复执行完整导出计算。正式文件导出仍对每一帧执行严格校验。

## 7. 导出 COLMAP/OpenCV W2C 外参

### 7.1 导出步骤

1. 完成人工轨迹并通过回读校验。
2. 点击“打开轨迹导出”。
3. 在“COLMAP / OpenCV 外参”区域选择“导出 JSON”“导出 CSV”或“导出 TXT”。
4. JSON 包含坐标约定和验证误差；CSV 是带表头的 W2C 表格；TXT 可直接作为 COLMAP `images.txt` 使用。

### 7.2 CSV 格式

```csv
index,image_name,qw_w2c,qx_w2c,qy_w2c,qz_w2c,tx_w2c,ty_w2c,tz_w2c
1,Virtual_Cam_000001.png,qw,qx,qy,qz,tx,ty,tz
```

四元数顺序固定为 `w,x,y,z`，并满足：

```text
X_camera = R_w2c * X_world + t_w2c
```

相机中心不写入 CSV，可按以下公式恢复：

```text
C_world = -transpose(R_w2c) * t_w2c
```

CSV 每行的七个外参数值可写入 COLMAP `images.txt`，不应再增加镜像、Y 轴翻转或 180 度滚转补偿。

### 7.3 TXT 格式

TXT 使用 COLMAP 标准的两行图像记录：

```text
# IMAGE_ID, QW, QX, QY, QZ, TX, TY, TZ, CAMERA_ID, NAME
1 qw qx qy qz tx ty tz 1 Virtual_Cam_000001.png

```

每条图像记录后的空行代表没有 `POINTS2D` 观测。导出文件统一写入 `CAMERA_ID=1`，使用前应确保配套 `cameras.txt` 中存在编号为 `1` 的相机内参。

### 7.4 坐标转换

SuperSplat/PlayCanvas 相机沿局部 `-Z` 观察，实体世界矩阵是 C2W。OpenCV/COLMAP 相机坐标为：

- `+X` 向右；
- `+Y` 向下；
- `+Z` 向前。

转换定义：

```text
D = diag(1, -1, -1, 1)
C2W_colmap = C2W_playcanvas * D
W2C_colmap = inverse(C2W_colmap)
           = D * inverse(C2W_playcanvas)
```

Pose 来自相机实体完整世界矩阵，而不是直接导出 PlayCanvas 内部四元数。

### 7.4 每帧校验

导出过程会检查：

- 四元数模长约等于 1；
- `transpose(R) * R` 约等于单位矩阵；
- `det(R)` 约等于 `+1`；
- `W2C * C2W` 约等于单位矩阵；
- 从 `R,t` 恢复的相机中心与世界矩阵位置一致；
- PlayCanvas/OpenCV 轴转换误差在容差内。

反射、剪切和非均匀缩放不能表示为标准 COLMAP 刚性 Pose，因此会被明确拒绝。

## 8. 导出轨迹图片

1. 打开相机导出面板，在“PNG 输出尺寸”中选择预设、当前渲染尺寸或“自定义”。
2. 自定义时直接填写宽度和高度；也可以点击“使用当前渲染尺寸”。
3. 点击“选择目录并保存 PNG”。
4. 选择具有写入权限的输出目录，等待所有帧渲染完成。

“当前渲染尺寸”显示在尺寸区域底部，它是浏览器中实时 WebGPU 画布的像素大小，会随窗口、侧栏布局和设备像素比变化。输出尺寸与当前画布相互独立：选择 1920 x 1080 或输入自定义值后，轨迹 PNG 会严格按该宽高渲染，完成后画布恢复原尺寸。所选宽高会保存在当前浏览器中，供下次继续使用。

若只导出当前视角的一张图片，使用“渲染 -> 图片”，在分辨率预设中选择“自定义”后填写宽高；“当前”选项会同时显示当前画布的实际像素尺寸。自定义尺寸不能超过界面显示的当前可用上限。

目录写入功能要求 Chrome 或 Edge 支持 File System Access API。

GPU framebuffer 的像素原点位于左下，普通图片文件的像素原点位于左上，因此程序内部固定执行一次 Y 方向换算。编辑器不提供用户可切换的 Y 翻转；轨迹 PNG 始终使用左上原点和规范正向，该操作只影响像素存储，不影响 Pose。不要再使用 CSS `scaleX(-1)`、`scaleY(-1)` 或修改四元数进行补偿。

## 9. WAN 数据包导出

在相机导出面板设置相机数量，并在上方“PNG 输出尺寸”设置宽度和高度，然后点击“导出 WAN K/T + COLMAP”。输出 ZIP 包含轨迹 JSON、相机参数和 COLMAP 文件结构；其内参与轨迹 PNG 使用相同的图像宽高。

仅需要外参时，应使用“导出 W2C CSV”，避免混入不需要的内参、FOV、target 或 camera center。

## 10. 性能建议

- 使用 RTX 启动器确认 HUD 第一行显示 `RTX 独立显卡`。
- 大模型编辑时关闭不需要的轨迹可视化。
- 图片匹配首次需要生成候选缩略图，后续会使用缓存。
- 场景、背景、色调映射或高斯内容发生变化后，渲染描述符缓存会自动失效。
- 不要把完整数据集、`node_modules`、`dist` 或浏览器配置提交到 Git。

## 11. 常见问题

### 页面没有自动打开

查看终端输出中的 `http://localhost:<端口>` 地址并手动打开。端口从 `3011` 开始自动选择。

### 提示 Node.js 版本过低

安装 Node.js 22 或更高版本，推荐 24.19.0 LTS。Windows 可重新运行启动器并确认 `winget` 升级；macOS 可执行 `brew install node@24` 或 `brew upgrade node@24`。升级后关闭旧终端，再重新运行启动脚本。

### RTX 启动后仍显示集成显卡

1. 更新 NVIDIA 驱动和 Chrome。
2. 在 Windows“设置 -> 系统 -> 显示 -> 图形”中将 Chrome 设置为高性能。
3. 关闭现有 RTX 专用窗口后重新运行 `SuperSplat RTX.cmd`。
4. 在 `chrome://gpu` 中确认 WebGPU 和实际适配器。

### 真实相机数量为零

确认选择的目录中存在文本格式的 `sparse/0/images.txt`，并且每个图像记录后保留对应的 POINTS2D 行。二进制 `images.bin` 不能替代当前文本读取入口。

### 找到了位姿但没有原图

确认 `images.txt` 中的图片名称与 `images/` 下的相对路径、文件名和大小写一致。只有 Pose 时仍可加载，但不能使用真实原图快速匹配和预览。

### 导出提示非均匀缩放或反射

将模型恢复为正的均匀缩放，或先将变换烘焙到 PLY。工具不会通过镜像图片掩盖非法旋转矩阵。

### 导出画面上下颠倒或左右镜像

先区分问题来源：

- 图片上下颠倒：检查 framebuffer 是否被重复翻转。
- 左右镜像：检查渲染器坐标约定或模型世界变换。
- Pose 方向错误：确认使用 W2C，且四元数顺序为 `w,x,y,z`。

不要用修改 Pose 的方式修复像素读取方向。

## 12. 开发、测试与发布

```sh
npm ci
npm run check
npm run build
npm run app:start
```

生成发布 ZIP：

```sh
npm run release:zip
```

Windows 也可双击 `package-release.cmd`，macOS 可双击 `package-release.command`。发布包输出到 `release/`。
